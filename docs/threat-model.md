# Threat model

## Trust boundary

UniFetch acts on one explicit URL after a Resolve click or OS share. Media saves require a download click. It does not crawl, enumerate, brute-force IDs, bypass access controls/private restrictions, discover unavailable content, request Instagram/Threads credentials, export user cookies or serialize browser sessions. The extension's Story support is limited to an explicit media id already present in the URL. Its Threads support is public-only and uses credential-free requests.

M5 introduces a remote metadata trust boundary: the configured Resolver sees the submitted public URL and upstream metadata transiently. It cannot be described as fully local. Media bytes remain between the client and source/CDN. T1B adds public Threads SSR metadata and, only for GIF placeholder posts, the exact post's embed page. The public implementation is auditable; an operator could deploy modified code, so users must trust the actual deployment as well as review source.

## Threats and reductions

| Threat                                                 | Reduction                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Malicious downloader server observes media or browsing | No media relay routes or media-body fetch; remote metadata visibility is disclosed. Only one explicitly submitted URL is processed. Deployment trust remains necessary.                                                                                                                                                                                                                                                                                                                          |
| SSRF / arbitrary outbound destinations                 | HTTPS Instagram/Threads content-reference parsing; exact hosts, no userinfo/custom ports; fixed Instagram or constructed Threads destinations; the raw user URL is never fetched. The Worker disables redirects. The extension follows only official Threads share redirects and same-shortcode username redirects; the final host, shortcode and SSR publisher must match, or the request fails closed.                                                                                         |
| Credential leakage                                     | No credential inputs/accounts; strict JSON schema and rejected Cookie/Authorization; credentials-omit client; anonymous Instagram cookie/CSRF context stays in one runtime closure and is discarded. Threads extension requests use `credentials: 'omit'` and never attach the browser session. A temporary host-scoped header rule changes only navigation headers, never cookies. No token/raw-header output/logging.                                                                          |
| Extension header manipulation                          | `declarativeNetRequestWithHostAccess` is restricted to non-tab extension requests (`tabIds: [-1]`) for `xmlhttprequest` on `https://www.threads.com/`, only sets `Sec-Fetch-*`/`Upgrade-Insecure-Requests`, blocks nothing, and is removed after each acquisition or on worker restart. Instagram requests, media/CDN requests and ordinary Threads browsing tabs cannot match; this was confirmed in real Chrome by comparing the actual request headers of an extension fetch and a tab fetch. |
| Persistent content history                             | No app history or storage bindings; no-store upstream/API; shell-only service worker; no analytics/telemetry. Infrastructure logs and browser caches need separate operator review.                                                                                                                                                                                                                                                                                                              |
| Resource exhaustion / unexpected structures            | POST JSON only, 4 KiB streamed-body cap, one URL, fixed requests, upstream timeouts, 1 MiB Instagram metadata cap, 4 MiB Threads HTML cap, strict normalized response capped at 100 assets. No enumeration/retries. No persistent rate-limit database is added.                                                                                                                                                                                                                                  |
| XSS / unsafe URL schemes                               | Vue escaped text, no raw HTML; exact input/share protocols/hosts; safe HTTP(S) direct asset URLs; API schema validation; no raw upstream response exposed. Third-party media origins still see direct requests.                                                                                                                                                                                                                                                                                  |
| Internal diagnostics leakage                           | Typed safe code/message only; no stack, upstream error dump, cookies, headers or CSRF in API/UI.                                                                                                                                                                                                                                                                                                                                                                                                 |
| Unwanted browser credential forwarding                 | Explicit origin CORS without credentials, strict preflight headers, credential-free API fetch and no UniFetch cookies/sessions.                                                                                                                                                                                                                                                                                                                                                                  |
| Share data in address/history                          | Replace query before resolution; no app persistence. Initial GET can still be observed by browser/host.                                                                                                                                                                                                                                                                                                                                                                                          |

## Remaining risks

The supplied Instagram web profile is unstable and may require authentication, be rate-limited or fail schema parsing. The Threads SSR/Relay payload and GIF embed are also internal platform surfaces and may change without notice. Failures stay typed; no alternate endpoint, login or proxy workaround is used. Direct media can be blocked by source/browser policy. A compromised dependency/host can change executable behavior. Provider logs, browser cache/history and download behavior are beyond application guarantees. No account-based access or persistent abuse-control database is introduced; operators should assess exposure before deployment.

M4C public Image/Carousel/Reel direct probes each returned BROWSER_RESTRICTION; M4D was intentionally skipped. The Web/PWA therefore keeps using the metadata Resolver. The separate unpacked extension performs authenticated Instagram requests inside the user's own browser and public-only Threads requests with `credentials: 'omit'`; it does not change the Web/PWA trust boundary, does not relay media and does not read cookies. See [supported content](supported-content.md) for the capability split.
